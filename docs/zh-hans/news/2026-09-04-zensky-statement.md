# 致 ZenSky Project 及『Misskey.Tokyo』的意见声明

2026年9月4日

我是『[Misskey Juice(JUICE)](https://github.com/Zel9278/misskey-juice)』的开发者 **ced([@c30](https://mk-juice.dev/@c30))**。

此次,针对 ZenSky Project 方面提供并运营的『Misskey.Tokyo』实例,该方发布了「[关于 Misskey.Tokyo 与 Misskey-juice 纠纷的本团体立场与声明](https://s-zensky.com/press-1.html)」,对此我分几点整理了自己的**个人见解**,内容如下。

## 1. 首先

我所开发的『Misskey Juice(JUICE)』,最初是在『[Misskey.art](https://misskey.art)』(以下简称 Art)上实现了"可对公告进行表情回应的功能",并提供给了 Art 的用户们使用。

由于该功能获得了 Art 用户们非常良好的反响,我本人便以"希望能有这样的独有功能"为主题,将『Misskey.art』的"可对公告进行表情回应的功能"继承过来,以『Misskey Juice(JUICE)』之名制定了新的计划,并个人开始了开发。

## 2. 关于『Misskey Juice(JUICE)』、『Juice Server』分支公开的经过

如上所述,『Misskey Juice(JUICE)』是以"希望能有这样的独有功能"为主要主题进行开发的,并每天都在引入新的想法。

2026年08月23日,当 [Askey](https://misskey.tokyo/@askey) 先生向我提出"能否请您运营 Misskey.Tokyo?"的商议时,我基于自己当时正在考虑的"能否针对 Art 已实现的功能,以独立分支的形式重新开发"这一构想,同意了 Askey 先生的提议,并就此展开了商谈。

然而,在09月03日公开的 ZenSky Project [新闻稿 No.1](https://s-zensky.com/press-1.html) 中,有如下记载(原文照录):

> 最初,我们收到了来自 Misskey-juice 开发者 c30 先生的大致如下提议:由于其正在开发 Misskey-juice,希望将其作为 Misskey.Tokyo 的半官方服务器引入。作为交换,他将听取 Misskey.Tokyo 希望具备的功能。

截至目前,『Misskey.Tokyo』既未实现『Misskey Juice(JUICE)』,也未向用户提供该功能,而且,声明中还出现了与最初商议内容完全不同的主张,以及暗示『Misskey Juice(JUICE)』被私自使用的内容。

导致这一事态发生的主要原因,包括:

- 双方认知上的偏差(我与 Askey 先生之间)
- 此后沟通过程中确认与传达的不足

等,结果导致在未能实现**充分对话**与**充分相互理解**的情况下,产生了较大的分歧。

今后,为避免再次发生此类情况,我将更加重视与用户之间的沟通,并继续努力开发『Misskey Juice(JUICE)』。

## 3. 致今后希望以『Juice Server』为主使用『Misskey Juice(JUICE)』的用户们

目前『Misskey Juice(JUICE)』仍处于开发阶段,我将**自己运营的实例**『Juice Server』作为**官方实例**进行运营,其目的在于对自己想要实现的功能进行先行测试,以及修复缺陷、调试等。

作为本实例的运营方针,我会提前启用一些自己也未曾预料到的缺陷或仍处于验证阶段的功能,验证性质较强。因此,今后将在多次更新中不断新增和修正各项功能,之后再向用户们提供**稳定版本**的『**Misskey Juice(JUICE)**』。

详情请参阅[关于本实例的运营方针](../about-juice-server.md)。

## 4. 最后

对于此次给 Askey 先生及各位用户带来的诸多不便,我在此致以诚挚的歉意。

『Misskey Juice(JUICE)』、『Juice Server』今后也不会仅凭我一人之力,而是希望能与大家携手,共同致力于更好的分支开发及服务提供。

今后也请大家继续多多关照『Misskey Juice(JUICE)』、『Juice Server』。
