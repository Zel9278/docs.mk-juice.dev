# 致 ZenSky Project 及『Misskey.Tokyo』的意見聲明

2026年9月4日

我是『[Misskey Juice(JUICE)](https://github.com/Zel9278/misskey-juice)』的開發者 **ced([@c30](https://mk-juice.dev/@c30))**。

此次,針對 ZenSky Project 方面提供並營運的『Misskey.Tokyo』實例,該方發布了「[關於 Misskey.Tokyo 與 Misskey-juice 糾紛的本團體立場與聲明](https://s-zensky.com/press-1.html)」,對此我分幾點整理了自己的**個人見解**,內容如下。

## 1. 首先

我所開發的『Misskey Juice(JUICE)』,最初是在『[Misskey.art](https://misskey.art)』(以下簡稱 Art)上實作了「可對公告進行表情回應的功能」,並提供給了 Art 的使用者們使用。

由於該功能獲得了 Art 使用者們非常良好的反響,我本人便以「希望能有這樣的獨有功能」為主題,將『Misskey.art』的「可對公告進行表情回應的功能」繼承過來,以『Misskey Juice(JUICE)』之名擬定了新的計劃,並個人開始了開發。

## 2. 關於『Misskey Juice(JUICE)』、『Juice Server』分支公開的經過

如上所述,『Misskey Juice(JUICE)』是以「希望能有這樣的獨有功能」為主要主題進行開發的,並每天都在引入新的想法。

2026年08月23日,當 [Askey](https://misskey.tokyo/@askey) 先生向我提出「能否請您營運 Misskey.Tokyo?」的商議時,我基於自己當時正在考慮的「能否針對 Art 已實作的功能,以獨立分支的形式重新開發」這一構想,同意了 Askey 先生的提議,並就此展開了商談。

然而,在09月03日公開的 ZenSky Project [新聞稿 No.1](https://s-zensky.com/press-1.html) 中,有如下記載(原文照錄):

> 最初,我們收到了來自 Misskey-juice 開發者 c30 先生的大致如下提議:由於其正在開發 Misskey-juice,希望將其作為 Misskey.Tokyo 的半官方伺服器引入。作為交換,他將聽取 Misskey.Tokyo 希望具備的功能。

截至目前,『Misskey.Tokyo』既未實作『Misskey Juice(JUICE)』,也未向使用者提供該功能,而且,聲明中還出現了與最初商議內容完全不同的主張,以及暗示『Misskey Juice(JUICE)』被私自使用的內容。

導致這一事態發生的主要原因,包括:

- 雙方認知上的偏差(我與 Askey 先生之間)
- 此後溝通過程中確認與傳達的不足

等,結果導致在未能實現**充分對話**與**充分相互理解**的情況下,產生了較大的分歧。

今後,為避免再次發生此類情況,我將更加重視與使用者之間的溝通,並繼續努力開發『Misskey Juice(JUICE)』。

## 3. 致今後希望以『Juice Server』為主使用『Misskey Juice(JUICE)』的使用者們

目前『Misskey Juice(JUICE)』仍處於開發階段,我將**自己營運的實例**『Juice Server』作為**官方實例**進行營運,其目的在於對自己想要實作的功能進行先行測試,以及修復缺陷、除錯等。

作為本實例的營運方針,我會提前啟用一些自己也未曾預料到的缺陷或仍處於驗證階段的功能,驗證性質較強。因此,今後將在多次更新中不斷新增和修正各項功能,之後再向使用者們提供**穩定版本**的『**Misskey Juice(JUICE)**』。

詳情請參閱[關於本實例的營運方針](../about-juice-server.md)。

## 4. 最後

對於此次給 Askey 先生及各位使用者帶來的諸多不便,我在此致以誠摯的歉意。

『Misskey Juice(JUICE)』、『Juice Server』今後也不會僅憑我一人之力,而是希望能與大家攜手,共同致力於更好的分支開發及服務提供。

今後也請大家繼續多多關照『Misskey Juice(JUICE)』、『Juice Server』。
